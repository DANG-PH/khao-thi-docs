Căn cứ
Code đang chạy trên bản demo (nhánh feat/ulsa-on-dinh của máy chủ, trang thi, trang quản trị) và tài liệu KT-NV-01 Tổng quan nghiệp vụ. Tên API trên sơ đồ là đường dẫn thật trong code (bỏ tiền tố /khao-thi-api), đã đối chiếu từng bước với code máy chủ và trang quản trị. So với nhánh develop: nhánh này có thêm tín hiệu kết nối lúc thi, Safe Exam Browser, nhập ma trận từ Excel; develop có thêm hiệu chỉnh điểm sau công bố.
Liên quan
KT-NV-01 (quy trình QT-01 đến QT-09, quy tắc BR), KT-TK-01 (thi trực tuyến cho ULSA)
Tài liệu này để làm gì. KT-NV-01 trả lời "ai làm gì, theo thứ tự nào". Tài liệu này trả lời "khi người dùng bấm thì hệ thống chạy thế nào": trang nào gọi API nào, API đọc ghi gì, gọi hệ thống nào khác, có rẽ nhánh hay lặp ở đâu. Mỗi luồng có một sơ đồ tuần tự đánh số bước, kèm mục tiêu, tác nhân, điều kiện, kết quả và quy tắc. Dùng để BA đối chiếu nghiệp vụ, Dev biết luồng đi qua đâu, Tester biết kiểm tra ở bước nào.

Thành phầnVai trò
Cán bộChuyên viên khảo thí, giảng viên, trưởng bộ môn, người ra đề, giám thị, cán bộ chấm, người duyệt điểm. Dùng trang quản trị.
Sinh viênDự thi trực tuyến trên trang thi; đăng ký phúc khảo qua hệ thống quy trình của trường (hệ thống đó gọi vào API khảo thí).
Trang quản trịỨng dụng web khao-thi-vwa: lập kế hoạch, ngân hàng câu hỏi, ma trận, bộ đề, lịch thi, coi thi, chấm, điểm. Ẩn hiện menu, nút theo quyền chức năng của tài khoản. Một vài màn đọc danh mục thẳng từ QLDT và ký số qua dịch vụ chung của trường.
Trang thiỨng dụng web thi_online cho thí sinh, chạy trên trình duyệt hoặc Safe Exam Browser.
nginxCổng vào: chuyển /khao-thi-api/ và /socket.io/ tới API, chia tải giữa các tiến trình API.
API khảo thíMáy chủ NestJS. Mọi nghiệp vụ khảo thí đi qua đây; là thành phần duy nhất đọc ghi dữ liệu khảo thí. Lúc thi trực tuyến chạy nhiều tiến trình song song.
MongoDBToàn bộ dữ liệu khảo thí: đợt thi, hồ sơ dự thi, ngân hàng, ma trận, bộ đề, ca thi, bài làm, kết quả, điểm.
RedisDùng chung giữa các tiến trình API: khóa chống nộp bài trùng; kênh chung của socket để lệnh đình chỉ, dừng thi tới máy thí sinh dù máy đó nối vào tiến trình nào.
Máy chủ fileẢnh, âm thanh (MP3) và tệp đính kèm của câu hỏi.
SSO (Keycloak)Đăng nhập cho cán bộ và sinh viên; cấp quyền chức năng cho trang quản trị; API kiểm tra token bằng bộ khóa công khai (JWKS) của SSO.
QLDTLớp học phần của đợt thi kèm sinh viên, đề cương; điều kiện học tập và công nợ để xét tư cách. Nhận điểm thi: bản nháp theo cài đặt đồng bộ điểm, bản chính thức khi công bố.
TCNSĐơn vị (tên đơn vị phụ trách học phần).
CSVCLịch sử dụng phòng, lịch của sinh viên và cán bộ, để ca thi không trùng phòng, trùng người.
Tài chínhTạo đợt thu lệ phí khi mở phúc khảo có thu phí.
Thông báoGửi thông báo cho sinh viên khi công bố lịch thi và khi công bố điểm.

SD-01 Đăng nhập và gọi API

Áp dụng: mọi màn hình, mọi tác nhânTác nhân: người dùng
sequenceDiagram
  autonumber
  actor ND as Người dùng
  participant WEB as Trang web
  participant SSO as SSO (Keycloak)
  participant API as API khảo thí
  ND->>WEB: Mở trang quản trị hoặc trang thi
  WEB->>SSO: Chuyển sang trang đăng nhập của trường
  ND->>SSO: Nhập tài khoản trường
  SSO-->>WEB: Mã truy cập (token) kèm vai trò
  WEB->>API: Gọi API, gửi token ở header Authorization
  activate API
  Note right of API: Kiểm tra chữ ký token bằng bộ khóa JWKS (giữ sẵn trong RAM 60 giây)
  alt Token sai hoặc hết hạn
    API-->>WEB: 401, trang chuyển về đăng nhập lại
  else Token hợp lệ
    Note right of API: Đọc người dùng, vai trò từ token, kiểm tra phân vùng dữ liệu nếu chức năng có bật
    API-->>WEB: Kết quả dạng success, data
  end
  deactivate API
  • Quyền chức năng (thấy menu, nút nào) do SSO cấp, trang quản trị ẩn hiện theo đó. Phần đề thi lọc thêm theo học phần được phân quyền. Ở phần điểm, chấm, API lọc dữ liệu theo học phần được phân quyền và túi bài được phân công.
  • SSO đổi khóa thì token mang khóa mới vẫn được chấp nhận: API tải lại bộ khóa ngay một lần.

SD-02 Lập kế hoạch thi (QT-01)

Mục tiêu: xác định đợt thi, học phần thi, danh sách thí sinh đủ điều kiệnTác nhân: chuyên viên khảo thíKết quả: hồ sơ dự thi của từng sinh viên, từng học phần
sequenceDiagram
  autonumber
  actor CV as Chuyên viên khảo thí
  participant QT as Trang quản trị
  participant API as API khảo thí
  participant QLDT as QLDT
  participant TCNS as TCNS
  participant DB as MongoDB
  CV->>QT: Tạo đợt thi: học kỳ, trình độ, hình thức đào tạo, các mốc thời gian (đồng bộ tư cách, công nợ, phân công)
  QT->>API: POST /ky-thi
  API->>DB: Lưu đợt thi
  CV->>QT: Màn Lớp thi: Khởi tạo học phần + tư cách dự thi
  QT->>API: PUT /ky-thi/:id/khoi-tao/hp-tu-cach
  activate API
  API->>QLDT: Lớp học phần của đợt thi kèm sinh viên, đề cương học phần
  QLDT-->>API: Lớp, học phần, sinh viên
  API->>TCNS: Tên đơn vị phụ trách học phần
  API->>DB: Học phần thi, hồ sơ dự thi từng sinh viên, trạng thái Chưa duyệt
  deactivate API
  CV->>QT: Màn Sinh viên thi: Cập nhật điều kiện học tập - công nợ
  QT->>API: PUT /sinh-vien-thi/init/dot-thi/:id
  activate API
  API->>QLDT: Điều kiện học tập, công nợ của từng sinh viên
  QLDT-->>API: Kết quả từng điều kiện
  API->>DB: Học tập Đạt và công nợ Đủ hoặc Miễn: Đủ điều kiện, học tập chưa duyệt: Chưa duyệt, còn lại: Không đủ điều kiện
  deactivate API
  Note over API,QLDT: Trong khoảng thời gian đồng bộ đặt ở đợt thi, API tự cập nhật lại 30 phút một lần
  opt Điều chỉnh từng sinh viên
    CV->>QT: Sửa trạng thái (ví dụ Hoãn thi)
    QT->>API: PUT /sinh-vien-thi/:id
  end
  CV->>QT: Chốt danh sách thí sinh
  QT->>API: PUT /lich-thi/sinh-vien-thi/chot/ky-thi/:id
  API->>DB: Đợt thi: đã chốt danh sách
  • Trạng thái hồ sơ dự thi: Chưa duyệt, Đủ điều kiện, Không đủ điều kiện, Hoãn thi (BR-02). Tư cách dựa trên điều kiện học tập và công nợ, cả hai lấy từ QLDT. Ngoài khoảng thời gian đồng bộ thì điều kiện học tập không bị ghi đè, trừ khi chọn bỏ qua thời hạn trên form cập nhật.
  • Sau khi chốt: màn Sinh viên thi ẩn thêm, sửa, nhập; API không cho khởi tạo lại học phần và tư cách (BR-03).
  • Thi trực tuyến chặn thí sinh "Không đủ điều kiện" và "Hoãn thi" ngay lúc lấy đề (SD-07), kể cả khi trạng thái đổi sau khi đã xếp ca.

SD-03 Ngân hàng câu hỏi: soạn, nhập, duyệt (QT-02)

Mục tiêu: có kho câu đã duyệt cho học phầnTác nhân: giảng viên, trưởng bộ mônĐiều kiện: được phân quyền theo học phầnKết quả: câu ở trạng thái Duyệt
sequenceDiagram
  autonumber
  actor GV as Giảng viên
  actor TBM as Trưởng bộ môn
  participant QT as Trang quản trị
  participant API as API khảo thí
  participant DB as MongoDB
  GV->>QT: Tạo khối kiến thức (chương)
  QT->>API: POST /khoi-kien-thuc
  alt Soạn trên form
    GV->>QT: Soạn câu: dạng, độ khó, nội dung, phương án, hình hoặc âm thanh
    QT->>API: POST /cau-hoi-ngan-hang/many
    alt Có câu giống hệt câu đã có của môn
      API-->>QT: Báo câu đã tồn tại, không lưu
    else Câu mới
      API->>DB: Lưu câu, trạng thái Chưa gửi
    end
  else Nhập file Word theo mẫu
    GV->>QT: Chọn file .docx
    QT->>API: POST /cau-hoi-ngan-hang/import-cau-hoi/:maMonHoc
    API->>DB: Tạo các khối kiến thức trong file mà môn chưa có
    API-->>QT: Câu hợp lệ, câu trùng với ngân hàng, lỗi theo từng câu
    GV->>QT: Sửa file đến khi hết lỗi, bấm Lưu
    QT->>API: POST /cau-hoi-ngan-hang/insert (chỉ câu hợp lệ)
    API->>DB: Lưu câu, trạng thái Chưa gửi
  end
  GV->>QT: Gửi duyệt câu đã chọn hoặc tất cả câu Chưa gửi
  QT->>API: PUT /cau-hoi-ngan-hang/trang-thai-cau/:maMonHoc (Chờ duyệt)
  TBM->>QT: Xem các câu chờ duyệt
  alt Đạt
    TBM->>QT: Duyệt câu đã chọn hoặc tất cả câu Chờ duyệt
    QT->>API: PUT /cau-hoi-ngan-hang/trang-thai-cau/:maMonHoc (Duyệt)
    API->>DB: Câu Duyệt, được kích hoạt
  else Chưa đạt
    TBM->>QT: Yêu cầu chỉnh sửa, ghi lý do
    QT->>API: PUT /cau-hoi-ngan-hang/trang-thai-cau/:maMonHoc (Yêu cầu chỉnh sửa)
    Note over GV,QT: Giảng viên sửa rồi gửi duyệt lại (quay về bước gửi duyệt)
  end
  • Trạng thái câu: Chưa gửi → Chờ duyệt → Duyệt hoặc Yêu cầu chỉnh sửa. Duyệt thì câu tự được kích hoạt, trạng thái khác thì tắt; ma trận và bộ đề chỉ rút câu đang kích hoạt (BR-04).
  • Dạng câu soạn được: trắc nghiệm một đáp án (kể cả câu có hình, âm thanh, chọn tranh), tự luận, câu nối, câu nhóm (BR-05). Độ khó: Dễ, Trung bình, Khó, Rất khó.
  • Câu giống hệt câu đã có của môn (cả nội dung lẫn phương án) không được thêm: soạn trên form thì báo lỗi, nhập Word thì câu đó nằm ở mục trùng và không được lưu (BR-07). Câu đã duyệt không sửa, xóa được trên màn ngân hàng (BR-08).
  • Hình, âm thanh của câu tải lên máy chủ file (chỉ nhận ảnh và MP3); video dùng đường dẫn (YouTube hoặc link file).

SD-04 Ma trận đề: lập trên form hoặc nhập Excel, duyệt (QT-03)

Mục tiêu: quy định cấu trúc đềTác nhân: người ra đề, trưởng bộ mônĐiều kiện: ngân hàng có câu đã duyệtKết quả: ma trận Duyệt
sequenceDiagram
  autonumber
  actor NRD as Người ra đề
  actor TBM as Trưởng bộ môn
  participant QT as Trang quản trị
  participant API as API khảo thí
  participant DB as MongoDB
  alt Lập trên form
    NRD->>QT: Thêm ma trận: tên, thời gian, có dùng tài liệu không
    loop Mỗi dòng: chương, độ khó, dạng câu, số câu
      QT->>API: GET /cau-hoi-ngan-hang/so-cau
      API-->>QT: Số câu đã duyệt còn trong kho cho dòng đang chọn
    end
  else Nhập từ Excel
    NRD->>QT: Tải mẫu Excel (đã chọn học phần)
    QT->>API: GET /ma-tran-de/mau-excel?maHocPhan
    API->>DB: Các chương, số câu đã duyệt theo dạng và độ khó
    API-->>QT: File mẫu: chương có sẵn, 4 dạng câu, bảng số câu trong kho
    NRD->>NRD: Gõ số câu trong Excel (Excel chặn gõ quá kho)
    NRD->>QT: Nhập từ Excel
    QT->>API: POST /ma-tran-de/doc-excel?maHocPhan
    API-->>QT: Dữ liệu ma trận, hoặc danh sách lỗi theo từng ô
    QT->>QT: Mở sẵn form Thêm ma trận
  end
  NRD->>QT: Lưu
  QT->>API: POST /ma-tran-de
  activate API
  API->>DB: Kiểm tra tên chưa có, dòng không trùng, mỗi dòng đủ câu đang kích hoạt
  API-->>QT: Ma trận ở trạng thái Chờ duyệt
  deactivate API
  TBM->>QT: Duyệt, yêu cầu chỉnh sửa lại, hoặc không duyệt
  QT->>API: PUT /ma-tran-de/:id (trạng thái, người duyệt)
  API->>DB: Duyệt thì ma trận được kích hoạt, trạng thái khác thì tắt
  • Ma trận có 4 dạng câu như ngân hàng: trắc nghiệm, câu nối, tự luận, câu nhóm. Mỗi dòng chỉ rút đúng dạng của dòng đó; câu nhóm không theo độ khó.
  • Hai dòng chỉ bị coi là trùng khi cùng chương, cùng độ khó và cùng dạng câu; một chương được lấy nhiều dạng ở cùng độ khó.
  • Dòng không đủ câu đang kích hoạt thì ma trận không lưu được (BR-10). Màn tạo bộ đề chỉ cho chọn ma trận Duyệt và đang kích hoạt (BR-09).

SD-05 Bộ đề: sinh mã đề, xem, sửa, xuất (QT-03)

Mục tiêu: có các mã đề hoàn chỉnh để thiTác nhân: người ra đềĐiều kiện: ma trận DuyệtKết quả: bộ đề gồm nhiều mã đề, mỗi câu kèm đáp án
sequenceDiagram
  autonumber
  actor NRD as Người ra đề
  participant QT as Trang quản trị
  participant API as API khảo thí
  participant DB as MongoDB
  NRD->>QT: Tạo bộ đề: chọn ma trận đã duyệt, số mã đề, cách sinh
  QT->>API: POST /bo-de-thi
  activate API
  loop Mỗi dòng ma trận
    API->>DB: Rút ngẫu nhiên đủ số câu đang kích hoạt, đúng chương, độ khó, dạng (câu nhóm không theo độ khó)
  end
  alt Sinh từ đề gốc
    Note right of API: Các mã đề cùng bộ câu, đảo thứ tự câu trong từng phần và đảo phương án
  else Sinh toàn bộ từ ngân hàng
    Note right of API: Mỗi mã đề rút bộ câu riêng, đảo phương án
  end
  API->>DB: Lưu bộ đề (mọi mã đề, kèm đáp án)
  API-->>QT: Bộ đề
  deactivate API
  NRD->>QT: Xem một mã đề
  QT->>API: GET /bo-de-thi/view-de/:idBoDe/:soDe/:hienThiDiem
  opt Sửa nội dung đề
    NRD->>QT: Sửa câu trong đề
    QT->>API: PUT /bo-de-thi/:id/update-noi-dung-bo-de
  end

SD-07 Thí sinh thi trực tuyến: vào thi, làm bài, nộp bài (QT-05)

sequenceDiagram
  autonumber
  actor SV as Sinh viên
  participant TT as Trang thi
  participant API as API khảo thí
  participant RD as Redis
  participant DB as MongoDB
  SV->>TT: Đăng nhập (SD-01), mở danh sách ca

  Note right of API: Kiểm tra SEB và dải IP (nếu bật), đã nộp thì báo đã làm, đã đến giờ, có tên trong ca, ca chưa dừng hoặc kết thúc, không bị đình chỉ, chưa quá hạn nộp, đủ điều kiện dự thi, mật khẩu (theo cài đặt)

  loop Trong giờ làm bài
    SV->>TT: Chọn đáp án (lưu ngay trên máy)
    TT->>API: POST /thi/back-up-cau-tra-loi (25 đến 35 giây, chỉ câu đã đổi)
    TT->>API: POST /thi/tin-hieu/:idCaThi (20 giây, bỏ lượt nếu vừa tự lưu, kèm số vi phạm mới)

  • Mỗi thí sinh có một kết quả: nộp hai lần cùng lúc thì lần sau bị chặn bằng khóa Redis; nộp lại khi đã có kết quả thì báo "đã nộp" (BR-19).
  • Mạng chậm lúc nộp mà máy chủ đã nhận bài: trang báo nộp thành công khi nhận lỗi "đã nộp", không kẹt lại.
