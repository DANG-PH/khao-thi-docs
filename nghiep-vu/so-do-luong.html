Căn cứ
Code đang chạy trên bản demo (nhánh feat/ulsa-on-dinh của máy chủ, trang thi, trang quản trị) và tài liệu KT-NV-01 Tổng quan nghiệp vụ. Tên API trên sơ đồ là đường dẫn thật trong code (bỏ tiền tố /khao-thi-api).
Liên quan
KT-NV-01 (quy trình QT-01 đến QT-09, quy tắc BR), KT-TK-01 (thi trực tuyến cho ULSA)
Tài liệu này để làm gì. KT-NV-01 trả lời "ai làm gì, theo thứ tự nào". Tài liệu này trả lời "khi người dùng bấm thì hệ thống chạy thế nào": trang nào gọi API nào, API đọc ghi gì, gọi hệ thống nào khác, có rẽ nhánh hay lặp ở đâu. Mỗi luồng có một sơ đồ tuần tự đánh số bước, kèm mục tiêu, tác nhân, điều kiện, kết quả và quy tắc. Dùng để BA đối chiếu nghiệp vụ, Dev biết luồng đi qua đâu, Tester biết kiểm tra ở bước nào.

1. Cách đọc sơ đồ

Ký hiệuÝ nghĩa
Hình người ở đầu cộtTác nhân (người dùng): chuyên viên, giảng viên, giám thị, thí sinh…
Hộp ở đầu cộtThành phần hệ thống: trang quản trị, trang thi, API khảo thí, cơ sở dữ liệu, hệ thống ngoài. Đường dọc bên dưới là "dòng đời" của thành phần đó.
Mũi tên liền, số thứ tựYêu cầu hoặc thao tác, theo thứ tự thời gian từ trên xuống

Thanh đặc trên dòng đờiThành phần đang xử lý yêu cầu

Khung optBước tùy chọn, chỉ xảy ra khi cần

Thành phầnVai trò
Cán bộChuyên viên khảo thí, giảng viên, trưởng bộ môn, người ra đề, giám thị, cán bộ chấm, người duyệt điểm. Dùng trang quản trị.
Sinh viênDự thi trực tuyến trên trang thi; xem điểm, đăng ký phúc khảo qua cổng sinh viên.
Trang quản trịỨng dụng web khao-thi-vwa: lập kế hoạch, ngân hàng câu hỏi, ma trận, bộ đề, lịch thi, coi thi, chấm, điểm.
Trang thiỨng dụng web thi_online cho thí sinh, chạy trên trình duyệt hoặc Safe Exam Browser.
nginxCổng vào: chuyển /khao-thi-api/ và /socket.io/ tới API, chia tải giữa các tiến trình API.
API khảo thíMáy chủ NestJS. Mọi nghiệp vụ đi qua đây; là thành phần duy nhất đọc ghi dữ liệu và gọi hệ thống khác. Lúc thi trực tuyến chạy nhiều tiến trình song song.
MongoDBToàn bộ dữ liệu khảo thí: đợt thi, hồ sơ dự thi, ngân hàng, ma trận, bộ đề, ca thi, bài làm, kết quả, điểm.
RedisDùng chung giữa các tiến trình API: khóa chống nộp bài trùng, bộ khóa SSO, kênh socket để lệnh đình chỉ, dừng thi tới đúng máy.
Máy chủ fileẢnh, âm thanh (MP3) của câu hỏi; tệp bài nộp.
SSO (Keycloak)Đăng nhập cho cán bộ và sinh viên; API kiểm tra token bằng bộ khóa công khai (JWKS) của SSO.
QLDTHọc kỳ, học phần, lớp học phần, sinh viên, đề cương, kết quả học tập, học phí; nhận lại điểm thi khi công bố.
TCNSĐơn vị, cán bộ (giám thị, cán bộ chấm, người ra đề).
CSVCPhòng, lịch sử dụng phòng, để lịch thi không trùng phòng, trùng người.
Thông báoGửi thông báo, nhắc lịch thi.

SD-01 Đăng nhập và gọi API

Áp dụng: mọi màn hình, mọi tác nhânTác nhân: người dùng
sequenceDiagram
  autonumber
  actor ND as Người dùng
  participant WEB as Trang web
  participant SSO as SSO (Keycloak)
  participant API as API khảo thí
  ND->>WEB: Mở trang quản trị hoặc trang thi
  WEB->>SSO: Chuyển sang trang đăng nhập của trường
  ND->>SSO: Nhập tài khoản trường
  SSO-->>WEB: Mã truy cập (token) kèm vai trò
  WEB->>API: Gọi API, gửi token ở header Authorization
  activate API
  Note right of API: Kiểm tra chữ ký token bằng bộ khóa JWKS (giữ sẵn trong RAM 60 giây)
  alt Token sai hoặc hết hạn
    API-->>WEB: 401, trang chuyển về đăng nhập lại
  else Token hợp lệ
    Note right of API: Kiểm tra quyền: vai trò, quyền theo chức năng, quyền theo học phần
    API-->>WEB: Kết quả dạng success, data
  end
  deactivate API
  • Phân quyền hai lớp: quyền theo chức năng (thấy màn hình nào) và, riêng phần đề thi, quyền theo từng học phần (soạn, nhập, gửi duyệt, duyệt câu; tạo, duyệt ma trận; tạo, xem, sửa bộ đề).
  • SSO đổi khóa thì token mang khóa mới vẫn được chấp nhận: API tải lại bộ khóa ngay một lần.

SD-02 Lập kế hoạch thi (QT-01)

Mục tiêu: xác định đợt thi, học phần thi, danh sách thí sinh đủ điều kiệnTác nhân: chuyên viên khảo thíKết quả: hồ sơ dự thi của từng sinh viên, từng học phần
sequenceDiagram
  autonumber
  actor CV as Chuyên viên khảo thí
  participant QT as Trang quản trị
  participant API as API khảo thí
  participant QLDT as QLDT
  participant DB as MongoDB
  CV->>QT: Tạo đợt thi: học kỳ, bậc, hình thức đào tạo, các mốc thời gian
  QT->>API: POST /ky-thi
  API->>DB: Lưu đợt thi
  CV->>QT: Khởi tạo học phần thi
  QT->>API: PUT /hoc-phan-thi/init/ky-thi/:id
  activate API
  API->>QLDT: Lớp học phần kết thúc trong kỳ, đề cương (hình thức thi)
  QLDT-->>API: Danh sách lớp, học phần
  API->>DB: Tạo học phần thi
  deactivate API
  CV->>QT: Xét tư cách dự thi
  QT->>API: PUT /ky-thi/:id/khoi-tao/hp-tu-cach
  activate API
  API->>QLDT: Sinh viên của lớp, kết quả học tập, học phí
  QLDT-->>API: Dữ liệu từng sinh viên
  API->>DB: Hồ sơ dự thi: Đủ điều kiện hoặc Không đủ điều kiện
  deactivate API
  opt Điều chỉnh từng trường hợp
    CV->>QT: Sửa tư cách, hoãn thi
    QT->>API: Cập nhật hồ sơ dự thi
  end
  CV->>QT: Chốt danh sách thí sinh
  QT->>API: PUT /lich-thi/sinh-vien-thi/chot/ky-thi/:id
  API->>DB: Khóa danh sách
  • Trạng thái hồ sơ dự thi: Chưa duyệt, Đủ điều kiện, Không đủ điều kiện, Hoãn thi (BR-02). Tư cách dựa trên kết quả học tập và công nợ học phí, cả hai lấy từ QLDT.
  • Sau khi chốt, không thêm hoặc xóa thí sinh trên màn tư cách dự thi được nữa (BR-03).
  • Thi trực tuyến chặn thí sinh "Không đủ điều kiện" và "Hoãn thi" ngay lúc lấy đề (SD-07), kể cả khi trạng thái đổi sau khi đã xếp ca.

SD-03 Ngân hàng câu hỏi: soạn, nhập, duyệt (QT-02)

Mục tiêu: có kho câu đã duyệt cho học phầnTác nhân: giảng viên, trưởng bộ mônĐiều kiện: được phân quyền theo học phầnKết quả: câu ở trạng thái Duyệt
sequenceDiagram
  autonumber
  actor GV as Giảng viên
  actor TBM as Trưởng bộ môn
  participant QT as Trang quản trị
  participant API as API khảo thí
  participant DB as MongoDB
  GV->>QT: Tạo khối kiến thức (chương)
  QT->>API: POST /khoi-kien-thuc
  alt Soạn trên form
    GV->>QT: Soạn câu: dạng, độ khó, nội dung, phương án, hình hoặc âm thanh
    QT->>API: POST /cau-hoi-ngan-hang/many
  else Nhập file Word theo mẫu
    GV->>QT: Chọn file .docx
    QT->>API: POST /cau-hoi-ngan-hang/import-cau-hoi/:maMonHoc
    API-->>QT: Kết quả đọc file: câu hợp lệ, câu trùng, câu lỗi
    GV->>QT: Xem trước, bấm Lưu
    QT->>API: POST /cau-hoi-ngan-hang/insert
  end
  API->>DB: Lưu câu, trạng thái Chưa gửi (bỏ câu trùng hệt câu đã có)
  GV->>QT: Gửi duyệt câu đã chọn hoặc tất cả
  QT->>API: PUT /cau-hoi-ngan-hang/trang-thai-cau/:maMonHoc (Chờ duyệt)
  TBM->>QT: Xem các câu chờ duyệt
  alt Đạt
    TBM->>QT: Duyệt
    QT->>API: PUT /cau-hoi-ngan-hang/trang-thai-cau/:maMonHoc (Duyệt)
  else Chưa đạt
    TBM->>QT: Yêu cầu chỉnh sửa, ghi lý do
    QT->>API: PUT /cau-hoi-ngan-hang/trang-thai-cau/:maMonHoc (Yêu cầu chỉnh sửa)
    Note over GV,QT: Giảng viên sửa rồi gửi duyệt lại (quay về bước gửi duyệt)
  end
  • Trạng thái câu: Chưa gửi → Chờ duyệt → Duyệt hoặc Yêu cầu chỉnh sửa. Chỉ câu Duyệt và đang kích hoạt mới được rút vào đề (BR-04).
  • Dạng câu soạn được: trắc nghiệm một đáp án (kể cả câu có hình, âm thanh, chọn tranh), tự luận, câu nối, câu nhóm (BR-05). Độ khó: Dễ, Trung bình, Khó, Rất khó.
  • Câu giống hệt câu đã có (cả nội dung lẫn phương án) không được thêm (BR-07). Câu đã duyệt không sửa được, chỉ bật hoặc tắt kích hoạt (BR-08).
  • Hình, âm thanh của câu tải lên máy chủ file (chỉ nhận ảnh và MP3); video dùng đường dẫn (YouTube hoặc link file).

SD-04 Ma trận đề: lập trên form hoặc nhập Excel, duyệt (QT-03)

Mục tiêu: quy định cấu trúc đềTác nhân: người ra đề, trưởng bộ mônĐiều kiện: ngân hàng có câu đã duyệtKết quả: ma trận Duyệt
sequenceDiagram
  autonumber
  actor NRD as Người ra đề
  actor TBM as Trưởng bộ môn
  participant QT as Trang quản trị
  participant API as API khảo thí
  participant DB as MongoDB
  alt Lập trên form
    NRD->>QT: Thêm ma trận: tên, thời gian, có dùng tài liệu không
    loop Mỗi dòng: chương, độ khó, dạng câu, số câu
      QT->>API: GET /cau-hoi-ngan-hang/so-cau
      API-->>QT: Số câu đã duyệt còn trong kho cho dòng đang chọn
    end
  else Nhập từ Excel
    NRD->>QT: Tải mẫu Excel (đã chọn học phần)
    QT->>API: GET /ma-tran-de/mau-excel?maHocPhan
    API->>DB: Các chương, số câu đã duyệt theo dạng và độ khó
    API-->>QT: File mẫu: chương có sẵn, 4 dạng câu, bảng số câu trong kho
    NRD->>NRD: Gõ số câu trong Excel (Excel chặn gõ quá kho)
    NRD->>QT: Nhập từ Excel
    QT->>API: POST /ma-tran-de/doc-excel?maHocPhan
    API-->>QT: Dữ liệu ma trận, hoặc danh sách lỗi theo từng ô
    QT->>QT: Mở sẵn form Thêm ma trận
  end
  NRD->>QT: Lưu
  QT->>API: POST /ma-tran-de
  activate API
  API->>DB: Kiểm tra mỗi dòng đủ câu đã duyệt, không trùng dòng
  API-->>QT: Ma trận ở trạng thái Chờ duyệt
  deactivate API
  TBM->>QT: Duyệt, yêu cầu chỉnh sửa lại, hoặc không duyệt
  QT->>API: PUT /ma-tran-de/:id (trạng thái)
  • Ma trận có 4 dạng câu như ngân hàng: trắc nghiệm, câu nối, tự luận, câu nhóm. Mỗi dòng chỉ rút đúng dạng của dòng đó; câu nhóm không theo độ khó.
  • Hai dòng chỉ bị coi là trùng khi cùng chương, cùng độ khó và cùng dạng câu; một chương được lấy nhiều dạng ở cùng độ khó.
  • Dòng không đủ câu đã duyệt thì ma trận không lưu được (BR-10). Chỉ ma trận Duyệt mới chọn được khi tạo bộ đề (BR-09).

SD-05 Bộ đề: sinh mã đề, xem, sửa, xuất (QT-03)

Mục tiêu: có các mã đề hoàn chỉnh để thiTác nhân: người ra đềĐiều kiện: ma trận DuyệtKết quả: bộ đề gồm nhiều mã đề, mỗi câu kèm đáp án
sequenceDiagram
  autonumber
  actor NRD as Người ra đề
  participant QT as Trang quản trị
  participant API as API khảo thí
  participant DB as MongoDB
  NRD->>QT: Tạo bộ đề: chọn ma trận đã duyệt, số mã đề, cách sinh
  QT->>API: POST /bo-de-thi
  activate API
  loop Mỗi dòng ma trận
    API->>DB: Rút ngẫu nhiên đủ số câu Duyệt, đang kích hoạt, đúng chương, độ khó, dạng
  end
  alt Sinh từ đề gốc
    Note right of API: Các mã đề cùng bộ câu, chỉ đảo thứ tự câu và phương án
  else Sinh toàn bộ từ ngân hàng
    Note right of API: Mỗi mã đề rút bộ câu riêng
  end
  API->>DB: Lưu bộ đề (mọi mã đề, kèm đáp án)
  API-->>QT: Bộ đề
  deactivate API
  NRD->>QT: Xem một mã đề
  QT->>API: GET /bo-de-thi/view-de/:idBoDe/:soDe/:hienThiDiem
  opt Sửa nội dung đề
    NRD->>QT: Sửa câu trong đề
    QT->>API: PUT /bo-de-thi/:id/update-noi-dung-bo-de
  end
  NRD->>QT: Xuất Word hoặc PDF, kèm hoặc không kèm đáp án
  QT->>API: POST /bo-de-thi/xuat-de hoặc /bo-de-thi/xuat-de-dap-an/:idBoDe/:soDe
  API-->>QT: Tệp đề (dùng cho thi viết)
  • Thi viết: xuất đề ra Word/PDF để in. Thi trực tuyến: gắn bộ đề vào ca thi (SD-06), mỗi thí sinh nhận một mã đề.
  • Sửa nội dung đề đã dùng để thi thì hệ thống chấm lại bài của sinh viên làm đề đó (BR-13).

SD-06 Tạo, kích hoạt, công bố ca thi trực tuyến (QT-04, QT-05)

Mục tiêu: có ca thi trực tuyến sẵn sàngTác nhân: chuyên viên khảo thíĐiều kiện: có bộ đề, danh sách thí sinh đã chốtKết quả: ca đã kích hoạt (có mật khẩu phòng), đã công bố
sequenceDiagram
  autonumber
  actor CV as Chuyên viên khảo thí
  participant QT as Trang quản trị
  participant API as API khảo thí
  participant CSVC as CSVC
  participant DB as MongoDB
  opt Cài đặt thi trực tuyến (một lần)
    CV->>QT: Quản trị, Cài đặt, Thi online: mật khẩu phòng, Safe Exam Browser, dải IP, mã hóa đề
    QT->>API: Lưu cài đặt hệ thống
  end
  CV->>QT: Tạo ca: phòng, học phần, bộ đề, giờ bắt đầu, số phút, giám thị, thí sinh
  QT->>API: POST /lich-thi
  activate API
  API->>CSVC: Phòng, sinh viên, cán bộ có trùng lịch không
  CSVC-->>API: Các lịch đang có
  alt Trùng lịch
    API-->>QT: Báo trùng lịch phòng, sinh viên hoặc cán bộ
  else Không trùng
    API->>DB: Lưu ca thi
    API-->>QT: Ca thi chưa kích hoạt
  end
  deactivate API
  CV->>QT: Kích hoạt ca
  QT->>API: PUT /lich-thi/:id (kích hoạt)
  API->>DB: Sinh mật khẩu phòng, mật khẩu từng thí sinh
  CV->>QT: Công bố lịch
  QT->>API: PUT /lich-thi/public/ky-thi/:id
  Note over QT,DB: Sinh viên, giám thị chỉ thấy ca sau khi công bố (BR-15)
  • Lịch không được trùng phòng, trùng lịch sinh viên hoặc cán bộ; API đối chiếu lịch sử dụng phòng ở CSVC (BR-14).
  • Giờ kết thúc làm bài = giờ bắt đầu + số phút của ca. Máy chủ nhận bài đến 2 phút sau giờ đó.
  • Safe Exam Browser, dải IP, mã hóa đề mặc định tắt; bật trong cài đặt khi trường yêu cầu.

SD-07 Thí sinh thi trực tuyến: vào thi, làm bài, nộp bài (QT-05)

Mục tiêu: thí sinh làm bài và có điểm ngayTác nhân: sinh viênĐiều kiện: ca đã kích hoạt, công bố; thí sinh có tên trong caKết quả: câu trả lời và kết quả thang 10 được lưu
sequenceDiagram
  autonumber
  actor SV as Sinh viên
  participant TT as Trang thi
  participant API as API khảo thí
  participant RD as Redis
  participant DB as MongoDB
  SV->>TT: Đăng nhập (SD-01), mở danh sách ca
  TT->>API: GET /lich-thi/me
  API-->>TT: Các ca đã công bố của thí sinh
  SV->>TT: Chọn ca, nhập mật khẩu phòng giám thị đọc
  TT->>API: GET /thi/sinh-vien/de-thi/:idCaThi
  activate API
  Note right of API: Kiểm tra SEB và dải IP (nếu bật), đã đến giờ, có tên trong ca, ca chưa dừng hoặc kết thúc, không bị đình chỉ, đủ điều kiện dự thi, mật khẩu phòng
  alt Vào lần đầu
    API->>DB: Chọn mã đề theo thứ tự trong danh sách ca, lưu bài làm (bản đề riêng kèm đáp án, máy đang làm)
  else Vào lại (tải lại trang, đổi máy)
    API->>DB: Đọc bài làm đã lưu, đúng đề cũ
  end
  API-->>TT: Đề đã bỏ đáp án đúng, hạn nộp theo giờ máy chủ
  deactivate API
  loop Trong giờ làm bài
    SV->>TT: Chọn đáp án (lưu ngay trên máy)
    TT->>API: POST /thi/back-up-cau-tra-loi (25 đến 35 giây, chỉ câu đã đổi)
    TT->>API: POST /thi/tin-hieu/:idCaThi (20 giây, bỏ lượt nếu vừa tự lưu, kèm số vi phạm mới)
    API->>DB: Giờ kết nối cuối, số vi phạm, bản lưu câu trả lời
  end
  SV->>TT: Nộp bài (hết giờ thì trang tự nộp, rải trong 30 giây)
  TT->>API: POST /thi/nop-bai-thi
  activate API
  API->>RD: Đặt khóa nộp bài theo ca thi và thí sinh (60 giây)
  alt Đang có lượt nộp khác
    API-->>TT: Bài thi đang được nộp
  else Giữ được khóa
    API->>DB: Chấm từng câu theo đáp án trong bài làm, lưu câu trả lời và kết quả thang 10
    API->>RD: Nhả khóa
    API-->>TT: Nộp thành công: điểm, số câu đúng, sai, chưa chấm (cài đặt Trả kết quả tắt thì ẩn)
  end
  deactivate API
  TT-->>SV: Màn hình kết quả bài thi
  • Mỗi máy chỉ giữ một bài: mở bài ở máy khác thì máy cũ bị khóa, giám thị thấy số lần đổi máy.
  • Chấm: trắc nghiệm một hoặc nhiều đáp án chọn đủ và đúng mới có điểm; câu nối, câu nhóm tính theo tỷ lệ cặp nối, câu con đúng; tự luận chưa chấm, tính 0 (BR-17). Điểm = tổng điểm câu đúng theo mức điểm ÷ điểm tối đa × 10 (BR-18).
  • Mỗi thí sinh có một kết quả: nộp hai lần cùng lúc thì lần sau bị chặn bằng khóa Redis; nộp lại khi đã có kết quả thì báo "đã nộp" (BR-19).
  • Mạng chậm lúc nộp mà máy chủ đã nhận bài: trang báo nộp thành công khi nhận lỗi "đã nộp", không kẹt lại.

SD-08 Giám thị coi thi trực tuyến: theo dõi, đình chỉ, dừng, kết thúc ca (QT-05)

Mục tiêu: giám sát ca thi và đưa điểm sang hồ sơ điểmTác nhân: giám thị (hoặc quản trị)Kết quả: ca kết thúc, điểm vào hồ sơ để rà soát
sequenceDiagram
  autonumber
  actor GT as Giám thị
  participant QT as Trang quản trị
  participant API as API khảo thí
  participant DB as MongoDB
  participant TT as Trang thi (máy thí sinh)
  GT->>QT: Mở ca thi của tôi
  QT->>API: GET /thi/giam-thi-ca-thi
  API-->>QT: Các ca được phân công, mật khẩu phòng
  GT->>TT: Đọc mật khẩu phòng cho thí sinh
  loop Mỗi 15 giây
    QT->>API: GET /thi/:idCaThi/list-sv-trang-thai
    API->>DB: Bài làm, log vào thi, kết quả, vi phạm
    API-->>QT: Từng thí sinh: đang làm, mất kết nối (quá 60 giây không tín hiệu), vi phạm, đổi máy, đã nộp
  end
  opt Xem bài làm của một thí sinh đã nộp
    QT->>API: GET /thi/chi-tiet-bai-lam-sinh-vien
  end
  opt Xem kết quả cả ca (tab Kết quả thi)
    QT->>API: GET /thi/ket-qua-thi/:idCaThi
    API-->>QT: Kết quả từng thí sinh theo danh sách ca (còn câu tự luận thì "đang chấm")
  end
  opt Đình chỉ một thí sinh
    GT->>QT: Đình chỉ, nhập lý do
    QT->>API: POST /thi/dinh-chi-thi
    API->>DB: Ghi đình chỉ
    API-)TT: Socket DINH_CHI: máy thí sinh khóa màn hình làm bài
    Note over API,TT: Tín hiệu, tự lưu, nộp kế tiếp của thí sinh này bị từ chối
  end
  opt Dừng cả ca
    GT->>QT: Dừng thi
    QT->>API: POST /thi/dung-thi
    API->>DB: Ca thi: đã dừng
    API-)TT: Socket DUNG_THI: khóa mọi máy trong ca
  end
  GT->>QT: Kết thúc ca
  QT->>API: GET /thi/:idCaThi/ket-thuc-ca-thi
  activate API
  loop Mỗi thí sinh trong ca
    API->>DB: Ghi điểm vào hồ sơ điểm (thí sinh không có hồ sơ dự thi thì bỏ qua)
  end
  API->>DB: Ca thi: đã kết thúc
  deactivate API
  Note over QT,DB: Điểm đi tiếp vào rà soát, chốt, duyệt, công bố (SD-10)
  • Trang thi gửi tín hiệu 20 giây một lần (hoặc tự lưu thay tín hiệu); màn giám thị coi là mất kết nối khi quá 60 giây không có tín hiệu.
  • Lệnh đình chỉ, dừng thi đi qua socket nên tới máy thí sinh ngay; kể cả rớt socket thì lượt gửi kế tiếp cũng bị máy chủ từ chối.
  • Kết thúc ca: thí sinh chưa nộp không gửi tiếp, không nộp được nữa.

SD-09 Thi viết: phách, túi bài, chấm, nộp điểm (QT-06)

Mục tiêu: chấm bài thi viết khách quan qua phách và hai lần chấmTác nhân: chuyên viên khảo thí, cán bộ chấm, cán bộ thẩm địnhKết quả: điểm bài được nộp, sẵn sàng rà soát
sequenceDiagram
  autonumber
  actor CV as Chuyên viên khảo thí
  actor CB as Cán bộ chấm
  participant QT as Trang quản trị
  participant API as API khảo thí
  participant DB as MongoDB
  CV->>QT: Sinh mã phách cho bài thi
  QT->>API: PUT /lich-thi/ma-phach/init/ky-thi/:id
  CV->>QT: Chia túi bài theo số bài mỗi túi
  QT->>API: PUT /hoc-phan-thi/tui-thi/init/ky-thi/:id
  API->>DB: Túi bài, danh sách bài theo phách
  CV->>QT: Phân công cán bộ chấm lần 1, lần 2 cho từng túi
  QT->>API: Lưu phân công chấm
  CB->>QT: Chọn học phần, chọn túi được giao
  CB->>QT: Nhập điểm theo phách (từng bài hoặc nhập Excel), xuất bảng điểm theo phách
  QT->>API: Lưu điểm chấm
  CB->>QT: Nộp điểm túi
  QT->>API: PUT /cham-thi/nop-diem/hoc-phan/:maHocPhan/ky-thi/:id
  opt Hủy nộp (trước khi chốt)
    QT->>API: PUT /cham-thi/huy-nop-diem/hoc-phan/:maHocPhan/ky-thi/:id
  end
  CV->>QT: Đặt ngưỡng chênh lệch, sinh túi thẩm định, phân công thẩm định
  QT->>API: PUT /diem-thi/tham-dinh/hoc-phan/:ma/ky-thi/:id
  Note over CB,DB: Cán bộ thẩm định chấm túi thẩm định như các bước trên
  • Bài thi viết được nhận diện bằng mã phách khi chấm (BR-20).
  • Điểm bài = trung bình điểm các lần chấm chính thức; có thẩm định thì lấy điểm thẩm định; có phúc khảo thì lấy điểm phúc khảo (BR-21). Vi phạm quy chế trừ theo phần trăm (BR-22). Điểm hợp lệ 0–10 (BR-23).
  • Thi trực tuyến không qua phách, túi: điểm đi thẳng từ kết thúc ca (SD-08) sang rà soát.

SD-10 Kết quả thi: rà soát, chốt, duyệt, công bố (QT-07)

Mục tiêu: kiểm soát, phê duyệt và công bố điểmTác nhân: chuyên viên khảo thí, người duyệt điểmKết quả: điểm công bố cho sinh viên, đồng bộ sang QLDT
sequenceDiagram
  autonumber
  actor CV as Chuyên viên khảo thí
  actor ND as Người duyệt điểm

  participant API as API khảo thí
  participant QLDT as QLDT
  CV->>QT: Rà soát: lọc điểm lệch, bài không có, xử lý vi phạm, khóa rà soát từng bài
  QT->>API: Lưu kết quả rà soát
  CV->>QT: Chốt điểm học phần
  QT->>API: PUT /diem-thi/chot/hoc-phan/:ma/ky-thi/:id
  ND->>QT: Đối chiếu, duyệt điểm
  QT->>API: PUT /diem-thi/duyet/hoc-phan/:ma/ky-thi/:id
  CV->>QT: Công bố điểm
  QT->>API: PUT /diem-thi/cong-bo/hoc-phan/:ma/ky-thi/:id

  end

    QT->>API: PUT /cham-thi/huy-cong-bo-diem/hoc-phan/:maHocPhan/ky-thi/:id
  end

  • Thời điểm đồng bộ điểm sang QLDT theo cấu hình: ngay, khi nộp điểm, khi chốt, hoặc theo luồng (BR-27).
  • Sửa điểm sau khi công bố đi qua quy trình hiệu chỉnh điểm (QT-08): đề xuất → bộ môn duyệt → khảo thí xác nhận, ký số lại bảng điểm.
